# Proposal

## Why

CanonKit already governs ownership, risk, proportional testing and OpenSpec handoffs, but its agent protocols leave evidence freshness, persistent debugging and independent review aspects implicit. Make those expectations explicit without adding agents, runtime machinery or resident instruction cost; behavioral efficacy remains UNMEASURED.

## What Changes

- Phase A: define evidence-based completion in `orchestrate`, referenced by Bob and Quinn; extend Bob with hypothesis-driven debugging and contextual reconsideration after about three failed fixes.
- Phase B: fill Scott's discovery gaps, distinguish requirements compliance from technical quality within existing reviews, and give Bob selective regression-first testing guidance.
- Phase C: extend existing handoffs with minimal resumable state and clarify readiness versus authorization and worktree cleanup.
- Reuse existing quality fixtures/judges for seven synthetic offline-calibrated scenarios; document telemetry coverage and its limits without adding collection or a dashboard.
- Preserve risk routing, LOW proportionality, security gates, installation behavior and the 2,500-word resident budget.

## Capabilities

### New Capabilities

- `engineering-delivery`: evidence, debugging, selective TDD and review protocols used by existing engineering agents.
- `product-discovery`: proportional requirements clarification under Scott's existing authority.
- `context-continuity`: compact, source-linked handoffs and authorized finalization through existing orchestration.

### Modified Capabilities

None. The initialized OpenSpec root has no existing main specs.

## Impact

MEDIUM instruction/configuration change, without CLI, public API, dependency, hook, version or installation changes. Canonical targets: `agents/bob.md`, `agents/scott.md`, `agents/quinn.md`, `skills/orchestrate/SKILL.md`; supporting team, eval and telemetry documentation and existing offline eval tests. The user authorizes implementation now, overriding the propose skill's planning-only pause. No paid evals, global installation, commit, push, merge, publish or deploy is authorized. Canonical OpenSpec setup and change artifacts are preserved; generated runtime integrations and personal settings are excluded from version control. PR review corrections restore baseline security gates and historical plans, and make project Graphify use proportional to structural need.
