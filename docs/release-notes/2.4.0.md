# canonkit 2.4.0

## For users

**Action required: none.** Existing installations keep working. Re-run
`npx canonkit@2.4.0 install` with your existing target flags to update installed
agents, hooks, blocks and core skills. Include `--wire-hooks` if you want to wire
hooks; installations and editor settings are not updated automatically.

- The on-demand `learning-loop` skill turns an explicitly requested investigation
  into an evidence-based instruction proposal. Changes remain subject to human
  review and authorization. It does not inject memories at session start,
  promote lessons automatically, or infer gate approval from activity records.
  Its contribution workflow separates preparation from authorization to publish.
- Ten optional stack packs are available through `canonkit add`: `typescript`,
  `cpp`, `csharp`, `java`, `python`, `react`, `rust`, `go`, `kotlin` and `swift`.
  They install project skills under `.agents/skills` and `.claude/skills`, without
  adding agents or joining the core install. `canonkit remove <stack>` removes
  tracked, unchanged copies conservatively; local edits and ambiguous ownership
  are preserved. Repeat `add` in each project to update an intact installed pack;
  a core reinstall does not update project packs.
- Concrete incidental findings have an on-demand capture procedure. Notes are
  kept out of the current change's scope; project issues and general instruction
  proposals each require review and publication authorization.
- New activity records omit dispatch descriptions and gated-command snippets.
  Existing logs are not rewritten, and remaining paths, names and identifiers
  still require sanitization before sharing.
- The shell-write heuristic now recognizes literal targets in `cp`, `mv`,
  in-place `sed`, `Copy-Item` and `Move-Item`, including removed move sources.
  This remains a heuristic: dynamic expressions, wrappers, directory child
  resolution and copied-content scanning are outside its scope. Harness gate
  modes and their enforcement limits are unchanged.
- Configured `highRisk.include` paths get a neutral confirmation message that
  names the project's protection, asks for validation and rollback, and retains
  the affected area's routing rules. Lint/test configuration is opt-in; there
  is no default list. Includes still take precedence over excludes.
- Optional `reference/canonkit.schema.json` provides editor completion and
  structural diagnostics. Associate it explicitly in your editor; the installer
  does not configure VS Code. Runtime validation remains authoritative, and
  unknown keys remain doctor WARNs rather than FAILs.
- Generated Codex agents now default to `gpt-6.1-sol` for the opus/sonnet tiers and
  `gpt-6-luna` for haiku. Set `CANONKIT_CODEX_MODEL=inherit` during `install` or
  `add` to omit the model field, or use a concrete ID to override all tiers.
  Reasoning effort remains mapped by tier. Existing files change only when
  regenerated; re-run `add <specialist>` separately for project specialists.
  Model availability depends on your Codex environment.
- Agent descriptions now state short non-triggers. The roster clarifies trivial
  changes, dependency routing and why HIGH-risk work needs a fresh independent
  review. Always-loaded source profiles remain below the 2,500-word limit.

Usage: [installation and stack packs](../install.md),
[hooks and editor schema](../hooks.md), [learning loop](../learning-loop.md),
and [incidental findings](../out-of-scope-issues.md).

## Verification and limits

The final feature suite on Windows passed with 832 tests: 829 passed, three
platform skips and no failures. Repository validation passed with 15 agents;
the dry-run package contained 53 files, including the schema. The release
workflow runs the CI matrix and secret scan on the tagged commit before npm
publication, with provenance and the existing environment approval gate.

Learning-loop and stack-pack behavioral effectiveness remains unmeasured;
offline fixtures do not establish real-model efficacy. Interactive editor
completion and a full JSON Schema validator run were not performed. No new
rubric scores are claimed.

This release retains the conservative uninstall behavior introduced in 2.3.0.
The deletion of byte-identical legacy `~/.agents/<core>.md` copies remains
reserved for 3.0. Activity history, backups and project data remain preserved.
