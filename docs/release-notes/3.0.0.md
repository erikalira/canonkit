# canonkit 3.0.0

**Action required: review the new Claude installation defaults before upgrading.**
This major version automatically applies supported native security settings and
migrates attributable legacy canonkit hooks when Claude is selected. Preview
from each repository you intend to update. Choose `--wire-hooks` explicitly if
you want to retain or reactivate the optional gates.

Status: prepared, not published. Owner: canonkit maintainers. Last reviewed:
2026-11-11. The commands below are for use **after publication**:

```bash
npx canonkit@3.0.0 install --claude --dry-run
npx canonkit@3.0.0 install --claude
npx canonkit@3.0.0 doctor
```

## What changes for users

- Claude-targeted installation writes supported controls to the validated
  current repository's `.claude/settings.json`, including with `--no-reference`.
  Outside a repository, repository security remains pending. File-read blocking
  requires Claude 2.1.257; file-write blocking requires 2.1.314. Shell sandbox
  switches use a conservative 2.1.302 floor and require available capabilities.
  Linux, WSL2 and macOS boundaries remain unverified; native Windows has partial
  permission coverage and no Claude OS shell sandbox.
- Installation sets `sandbox.network.strictAllowlist: true` in Claude **user**
  settings from 2.1.219, the sole newly added global policy key. Protection
  against repository-supplied destinations and proxy ports requires 2.1.285.
  No destinations are added. This setting covers sandbox proxy traffic, not
  native Windows shell traffic or every tool surface.
- Your selected Claude approval mode, saved allow rules and stronger existing
  restrictions are preserved. Supported sandbox configuration refuses
  unsandboxed retries and uses regular permission review; existing personal
  sandbox approval choices are preserved. Settings do not prove containment.
- Without `--wire-hooks`, installation removes only attributable canonical
  canonkit/meu-time hook registrations from active user settings and the current
  repository settings. Ambiguous commands, wrappers and dot-segment paths remain
  with warnings. Local and managed settings, other repositories, hook payloads
  and activity history remain. Start a fresh Claude session and inspect `/hooks`
  for registrations from preserved sources.
- `--no-reference` still reconciles an existing managed Claude instruction block,
  including on retries after partial failure. It creates no instruction document
  or block and preserves bytes outside the managed block. Completed settings
  writes remain if a later stage fails; resolve the reported conflict and retry.
- `uninstall --project` reverses only attributable security settings in the
  current repository. Private snapshots and per-key provenance support undo
  while preserving later edits. Uninstall never resurrects migrated hooks.
  Global uninstall does not scan repositories; project uninstall leaves the
  user-scoped network lock and global installation in place.
- `doctor` reports read-only security diagnostics for Claude, Codex and OpenCode,
  separating severity from coverage. Configured controls can still have partial,
  unavailable or unknown coverage. Codex and OpenCode receive diagnosis only;
  automatic enforcement changes target Claude.
- Windows tracked file replacement retries temporary `EPERM`, `EACCES` and
  `EBUSY` rename failures, with up to 1.5 seconds of backoff. Persistent errors
  preserve the original file and recovery receipt; concurrent edits stop the write.

See [installation, version coverage and reversal](../install.md#native-security-per-repository)
and the [hook migration runbook](../hooks.md#returning-to-native-approvals).

## Model selection (breaking)

Canonkit no longer ships a model for any agent. You choose models from what your
harness reports; until you do, every agent runs on the session's model and effort.

- **BREAKING:** agent frontmatter declares `need: light|standard|deep` instead of
  `model:`. A `model:` line now fails validation, and the message names `need:`.
  Shipped agents moved `opus` → `deep` (archie, iris) and `sonnet` → `standard`
  (the rest). If you keep a fork of an agent, apply the same mapping.
- **BREAKING:** the Codex model table and `CANONKIT_CODEX_MODEL` are removed.
  Codex, OpenCode and Copilot agents are generated with no model or reasoning
  effort, so they inherit the session's, until you choose. A set
  `CANONKIT_CODEX_MODEL` prints one warning and is otherwise ignored. Codex agents
  no longer get the fixed per-tier effort (`high` for archie and iris, `medium` for
  the others); choose one with `models setup --codex`, below.
- **New:** `canonkit models refresh`, `models setup [--project]` and
  `models show [--json]`; the interactive `install` offers the same choice
  right after its harness menu. Choices live in `~/.canonkit/models.json` and, per
  project, in `.canonkit/models.json`. This release applies them to Claude Code:
  `install` writes `model:` and `effort:` into `~/.claude/agents`, and planned
  dispatches pass them as Agent tool parameters (the `orchestrate` skill). `doctor`
  warns when a choice is missing from the latest discovery, unverified, or the
  discovery is older than 30 days.
- Claude Code agents are now generated instead of copied. With no choices they
  are byte-identical to the source.
- **Codex choices:** `npx canonkit models setup --codex` selects a model and
  reasoning effort per need level or agent; the effort menu depends on the selected
  model. Run `npx canonkit install --codex` afterwards, and from each repository
  with project choices, to create project core agents where those differ from your
  user defaults. `canonkit add <specialist>` uses the merged project and user
  choices. Unset fields inherit the session, and existing installations must
  reinstall to apply choices.
- `models refresh --codex` reads the experimental `codex debug models` catalog,
  from the network, a local cache or bundled data; a listed model does not
  establish account access. `models show` and `doctor` report sources and warn
  about unverified or incompatible pairs without starting Codex, and flag project
  core files not yet installed or no longer matching the choices.
- Project core files are tracked in the project's install receipt. An existing
  same-name file and later edits are preserved; `uninstall --project` removes only
  receipt-owned files that still match. Global Codex agents keep using user choices.

After upgrading, run `npx canonkit install` so installed agents drop their old
`model:` line. Optionally run `npx canonkit models setup` and install again.
Details: [Choosing models](../install.md#choosing-models) and
[ADR 0006](../adr/0006-runtime-model-discovery.md).

## Clearer command output

- `install` and `doctor` now print a short grouped summary by default. Every
  warning and failure still appears by name, and counts include everything the
  full output would show. `--verbose` prints every step and row in full, as before.
  `--verbose` is rejected on other commands.
- Fixed: the CLI exited silently, without running, when launched through `npx` or a
  global install, because the launcher link or shim did not match the script path.
  The check now compares real paths.

## Team instructions

- Verification by reach: while editing, agents are instructed to run the tests of
  the touched area, of its consumers and the invariant tests the change can
  reach; the full suite and project validations run once, after the last edit. A
  full-suite failure must be traced to the change or shown to predate it before
  delivery is called verified. Dispatch briefs carry existing evidence, and
  reviewers do not repeat a fresh, matching full-suite result. See the
  `orchestrate` skill; run `npx canonkit install` to receive the updated block.
  Behavioral effect is unmeasured.
- The always-loaded instruction ceiling rises from 2,500 to 3,000 words, so a new
  rule no longer forces cutting another one. The audit rubric is unchanged: its
  context-cost score stays 10 up to about 3,050 words.

## Maintainers

- The test suite runs in about 134 seconds, down from minutes of serial work: CLI
  tests use an isolated `PATH` with no real `claude` or `codex`, stub the Windows
  ACL spawns through a test-only preload, share one harness, and run in parallel
  files. At least one Windows test still reads the real DACL back. `npm test`
  remains the full publish gate.

## Verification and release limits

Before the metadata version bump, the recorded Windows regression suite passed:
880 tests, 877 passed, no failures and three platform skips. After the final
implementation delta, 27 focused tests passed; repository validation also passed.
Version preparation confirmed matching package/lockfile versions, CLI version
3.0.0 and a passing packaging dry-run containing 55 files. The full suite was not
rerun for the metadata bump. These disposable-home tests and static/offline
checks do not establish runtime containment on any platform.

After the Windows rename-retry fix, the full Windows regression suite passed:
890 tests, 886 passed, no failures and four platform skips. Repository validation
passed, and Quinn's independent review found no blockers. The rename regression
tests inject OS errors; they do not identify the process behind a real file lock.

Real platform boundary validation and final readiness remain open as
[OpenSpec tasks 5.2 and 5.4](../../openspec/changes/environment-aware-security/tasks.md).
The required real-model routing evaluation has not been rerun before release.
[Maintenance guidance](../maintaining.md) additionally requires quality evaluation
when an agent body with a quality case changes; this change does not alter agent
bodies. Preparing this version does not satisfy the pending gates or declare
release readiness. The UI-focused visual workflow remains planning only.

Publication must follow the existing [release procedure](../releasing.md),
including CI, secret scanning, tagged-package review, deployment approval and
provenance.
