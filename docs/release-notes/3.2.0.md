# canonkit 3.2.0

## For users

**Action required: none.** Existing installations keep working. Re-run
`npx canonkit@3.2.0 install` with your existing target flags to pick up the
changes below. From a terminal, install now asks before changing two kinds of
Claude settings; without a terminal (`--yes`, CI, `--dry-run`, `TERM=dumb`) it
behaves as 3.1.0 did, key by key, and additionally prints the runtime-reads
snippet (and a warning for any unhandled runtime location) instead of writing it.

- **Install review prompt (terminal only).** After preflight and before the first
  write, `install` asks at most two grouped questions: whether to add the detected
  runtime read folders (below), and whether to apply the recommended value to
  repository settings that are weaker than the strict sandbox profile
  (`sandbox.enabled: false`, `failIfUnavailable: false`,
  `allowUnsandboxedCommands: true`, either `permissions.block*OutsideWorkingDirectories:
  false`, or `autoAllowBashIfSandboxed: false`). The answer is *Apply*, *Keep* or
  *Choose per key*. No question has a default: Enter or any other answer asks
  again (yes/no questions accept only y/yes/n/no), a closed input counts as
  Keep or decline, and Ctrl-C aborts before anything is written. Each line names the recommended value and why. Nothing is asked
  when nothing is missing or weaker. Values in `settings.local.json` are never
  written. See [installation](../install.md#security-review-during-install).
- **The 3.0.0 leftover `autoAllowBashIfSandboxed: false`.** Installing the prior
  release over a 3.0.0 project kept the `false` that 3.0.0 wrote, so every
  sandboxed command still prompted. An interactive install now offers to switch
  it to `true`.
  Without a terminal the explicit value is still preserved, with the recommendation
  printed, as in 3.1.0.
- **Runtime `allowRead` in user settings.** `install` detects the nvm and pipx
  (graphify) folders in use, compares them item by item with your existing
  `sandbox.filesystem.allowRead` (equivalent spellings and broader entries cover),
  and, after you confirm, appends only the missing ones in `~/` form without
  touching your entries. Declined, or without a terminal, it prints the snippet.
  Other managers (volta, fnm, asdf) are reported as unhandled, never guessed.
  `uninstall` removes only the items canonkit appended. This removes the manual
  step for nvm and pipx installs in [tools](../tools.md).
- **`doctor` reports runtime read coverage.** `WARN security claude runtime-reads`
  for a detected runtime folder missing from user `allowRead`, and for an entry
  that covers the whole home directory; `OK` when covered. The approval
  recommendation now mentions that `install` offers the change from a terminal.
- **Empty settings files are valid.** A 0-byte, whitespace-only or BOM-only
  `settings.json` (user or repository) is read as `{}` instead of failing with
  "Invalid JSON", as `settings.local.json` already was. Malformed JSON still stops
  the install before any write.
- **README: Recommended security settings.** The recommended user and repository
  `settings.json` side by side, with a reason per key. `npm run validate` fails if
  the section's JSON blocks (except the `allowRead` example values) or reasons
  differ from the installer output.

Security-gate behavior is otherwise unchanged from 3.1.0.

Usage: [installation and security coverage](../install.md),
[tools](../tools.md). Design:
[`openspec/changes/security-settings-scope-and-confirmation`](../../openspec/changes/security-settings-scope-and-confirmation/proposal.md).

## Verification and limits

On the release branch, the Linux (WSL2) `npm test` run completed 1203 tests:
1182 passed, 21 skipped and 0 failed. `npm run validate` (portable) passed; the
Bash syntax checks were not run. Design question D7 was checked in a real
Claude Code session on WSL2: with the working-directory read block on, a
project-level `allowRead: ["~/.nvm"]` did not make `node` reachable once the
entry was removed from user settings (`node: command not found`). Claude Code
ignores project-level `allowRead` there, which is why canonkit writes runtime
reads only to user settings.

Version 3.2.0 is prepared in `package.json` and the lockfile; it is not tagged or
published. Publication follows the existing CI matrix, secret scan, tag-on-main
check and `npm` environment approval. See [releasing](../releasing.md).

## Not in this release

- Runtime read detection covers nvm and pipx only. Volta, fnm, asdf and other
  managers are reported as unhandled locations and nothing is proposed for them.
- Native Windows has no runtime-read support: the sandbox does not apply there.
