# canonkit 3.2.0

**Action required: none.** Existing installations keep working. Re-run
`npx canonkit@3.2.0 install` with your existing target flags to pick up this release.

## For users

### Guided install

The install flow now starts with an unselected runtime menu, asks whether to
configure the current project, previews recommended model and security changes,
and requests final confirmation before writing. Graphify and OpenSpec are
preselected in the project tool menu. Use **keep current** to leave discovered
model choices and security settings unchanged, or **customize** to choose model
levels and security rows. “Keep current” is available when either existing
model choices or security changes are present. Recommended setup preserves
saved model levels when discovery has no match, and applies staged Codex model
choices consistently to user and project agents.
OpenSpec now uses the harnesses selected at the start of install, without a
second harness prompt. Standalone `tool add openspec` keeps its harness choice.

Decision previews are printed immediately in the default compact output, so
recommended changes and the final summary are visible before their prompts.
Interactive previews now use explicit phase headings and text markers, with a
compact unchanged summary and result headings that distinguish completion,
cancellation, failure and dry runs. Piped output remains plain text.

- `--recommended` applies recommended model choices and security answers in
  non-interactive runs. `--no-project` skips project configuration and project
  security. The pre-existing no-flag non-terminal behavior is preserved.
- Recommended Claude levels are opus, sonnet and haiku. Codex recommendations
  match discovered `gpt-<version>-<tier>` IDs and choose the newest numeric
  version independently for each tier; unknown or suffixed IDs are ignored.
- Missing strict security keys appear as added (`+`) rows and follow the
  interactive answer. Automatic bash approval is written only when the complete
  strict sandbox profile is effective.

See [installation](../install.md#guided-install-flow) for the screens, markers,
scope terms and dry-run commands.

- **Security review during guided install.** The recommended-setup preview lists
  missing and weaker security settings alongside the model choices. Accepting
  recommended applies the listed changes; keep current writes none of those
  model or security choices. Customize offers a select for detected runtime read
  folders and a checked multi-select for the other security changes. These are
  arrow-key menus with explicit defaults, followed by the final write
  confirmation. EOF, Esc and Ctrl-C cancel before installation writes begin.
  Values in `settings.local.json` are never written. See
  [installation](../install.md#security-review-during-install).
- **The 3.0.0 leftover `autoAllowBashIfSandboxed: false`.** Installing the prior
  release over a 3.0.0 project kept the `false` that 3.0.0 wrote, so every
  sandboxed command still prompted. An interactive install now offers to switch
  it to `true`.
  Without a terminal and without `--recommended`, the explicit value is still
  preserved, with the recommendation printed, as in 3.1.0.
- **Runtime `allowRead` in user settings.** `install` detects the nvm and pipx
  (graphify) folders in use, compares them item by item with your existing
  `sandbox.filesystem.allowRead` (equivalent spellings and broader entries cover),
  and, after you confirm, appends only the missing ones in `~/` form without
  touching your entries. Keep current, or a non-terminal run without
  `--recommended`, prints the snippet instead.
  Other managers (volta, fnm, asdf) are reported as unhandled, never guessed.
  `uninstall` removes only the items canonkit appended. This removes the manual
  step for nvm and pipx installs in [tools](../tools.md).
- **`doctor` reports runtime read coverage.** `WARN security claude runtime-reads`
  for a detected runtime folder missing from user `allowRead`, and for an entry
  that covers the whole home directory; `OK` when covered. The approval
  recommendation now mentions that `install` offers the change from a terminal.
- **Empty settings files are valid.** A 0-byte, whitespace-only or BOM-only
  `settings.json` (user or repository) is read as `{}` instead of failing with
  "Invalid JSON", as `settings.local.json` already was. Malformed JSON still stops
  the install before any write.
- **README: Recommended security settings.** The recommended user and repository
  `settings.json` side by side, with a reason per key. `npm run validate` fails if
  the section's JSON blocks (except the `allowRead` example values) or reasons
  differ from the installer output.

Security-gate behavior is otherwise unchanged from 3.1.0.

## Verification and limits

The latest local Linux `npm test` run completed 1232 tests:
1211 passed, 21 skipped and 0 failed. This does not establish the status of the
GitHub CI matrix. Local `npm run validate` and `npm run validate:full` passed,
including Bash syntax checks in full mode. Design question D7 was checked in a real
Claude Code session on WSL2: with the working-directory read block on, a
project-level `allowRead: ["~/.nvm"]` did not make `node` reachable once the
entry was removed from user settings (`node: command not found`). Claude Code
ignores project-level `allowRead` there, which is why canonkit writes runtime
reads only to user settings.

Version 3.2.0 is prepared in `package.json` and the lockfile; it is not tagged or
published. Publication follows the existing CI matrix, secret scan, tag-on-main
check and `npm` environment approval. See [releasing](../releasing.md).

## Not in this release

- Runtime read detection covers nvm and pipx only. Volta, fnm, asdf and other
  managers are reported as unhandled locations and nothing is proposed for them.
- Native Windows has no runtime-read support: the sandbox does not apply there.
