# canonkit 3.0.1

## For users

**Action required: none.** Existing installations keep working. Re-run
`npx canonkit@3.0.1 install` with your existing target flags to update agents,
blocks and core skills; installed files change only when you run the installer.
**WSL users:** read the first item, which changes what `install` writes when
your only `claude` is the Windows one.

- **WSL: Windows binaries are ignored by three more commands.** On WSL,
  `install --wire-hooks` (the OpenCode version check), `models refresh` (and the
  catalog refresh inside `install`) and the security checks now look for
  `opencode`, `claude`, `bwrap` and `socat` on the Linux side only. A Windows
  copy reached through interop is reported and never run, the same rule
  `tool add` and `tool list` already follow. Drives are read from
  `/proc/self/mounts`. Outside WSL nothing changes, and there is no flag to
  allow Windows binaries.
  - **Behavior change.** If your only `claude` on WSL is the Windows one,
    `install` can no longer read its version. Settings that need a version
    (file-read and file-write blocks, sandbox switches, the network lock) are
    then written less than before. `install` says so (`! security claude: a
    Windows copy at <path> was ignored ...` in the short summary; not shown in
    `--dry-run`, which does not probe versions). `npx canonkit doctor` shows
    `security claude version: unknown; a Windows copy at <path> was ignored (it
    reads Windows settings, not these)`, and `models refresh` reports
    `claude found only on the Windows side; not run through WSL interop`. To get
    the previous coverage, install Claude Code inside WSL and run
    `npx canonkit install` again. Nothing an earlier install wrote is removed.
  - With only a Windows `opencode`, `install --wire-hooks` refuses, names the
    ignored copy and asks for OpenCode 2 or later installed on the Linux side.
- **Tool installs on Linux and WSL.** `tool add` and `tool list` ignore Windows
  copies of a tool (such as an npm shim reached through `/mnt/c`), say so, and
  print the pinned install command. Graphify now has Linux and WSL install
  instructions through `pipx`, and the tool's own steps run with a `PATH` that
  has no Windows programs on it. When the Claude Code sandbox hides a tool's
  folder (`~/.nvm`, `~/.local/share/pipx`), the message points to the
  `sandbox.filesystem.allowRead` setting; canonkit only prints this and never
  edits your settings. See [tools](../tools.md).
- **`canonkit git-ignore-sandbox-files [--remove] [--dry-run]`** (new, opt-in,
  per project). The Claude Code sandbox leaves 0-byte placeholder files in the
  project (`.bashrc`, `.mcp.json`, `.claude/settings.local.json` and others).
  The command writes a managed block to the clone's `.git/info/exclude` so Git
  stops listing them. It never touches the sandbox or any permission, only
  names that are 0-byte, untracked regular files at that moment, and `--remove`
  removes only its own block. `doctor` now warns about placeholders that are not
  excluded and tolerates an empty or `/dev/null` placeholder where it used to
  report invalid JSON. Run it outside the sandbox. See
  [ADR 0007](../adr/0007-sandbox-placeholder-exclude.md) and
  [installation](../install.md).
- **`canonkit tool add openspec --harness <list>`** chooses which harnesses
  OpenSpec writes skills and commands for: `claude`, `codex`, `opencode`,
  `github-copilot` (comma-separated). The default stays `claude,codex`. It only
  adds; it does not remove harnesses configured earlier. See
  [tools](../tools.md#openspec-harnesses---harness) and
  [ADR 0008](../adr/0008-openspec-harness-choice.md).
- **Reading a FIFO no longer hangs two paths.** The legacy hook-runner scan and
  the `doctor` text reader skip non-regular files. Other file reads are not yet
  covered (see below).
- **Team instructions** (agents, the `orchestrate` skill and the blocks) were
  tightened:
  - Scott names the forbidden side effect in MEDIUM/HIGH acceptance criteria and
    records research sources.
  - Archie classifies a contract change as additive or breaking.
  - Bob checks for existing utilities before writing new ones, and requires a
    test net before a MEDIUM refactor.
  - Gard covers agentic and MCP flows and the history of a repository before it
    is published.
  - Pipe states what a rollback does not revert.
  - Perry counts an optimization only when correctness stays green.
  - Spencer reuses one source of truth.
  - `orchestrate` gains rules for lanes of parallel writers, looped runs,
    irreversible external actions and open decisions for the user.
  - The Claude block asks for `AskUserQuestion` on user-owned decisions, the
    Codex and OpenCode blocks name their own question tools, and all blocks
    say to keep the user's Git-configured author identity and to add no
    co-author unless asked.

Security-gate behavior is otherwise unchanged from 3.0.0.

Usage: [tools](../tools.md), [installation and security coverage](../install.md),
[ADR 0001](../adr/0001-tool-namespace-integrate-only.md) for the WSL filter.

## Not in this release

- `git` calls still resolve binaries as before, and do not yet drop `GIT_*` or
  set `core.fsmonitor=false`.
- Several file reads are still unguarded against a FIFO (log rotation during
  `install` and `AGENTS.md` handling in `tool add`).
These are separate, unfinished changes.

## Verification and limits

On the working tree prepared for this release (Linux/WSL2), the full `npm test`
ran 1142 tests: 1121 passed, 21 skipped, 0 failed. Each production call site
of the WSL filter has an end-to-end test using a fake Windows drive that
proves the Windows copy is never executed; dropping the filter argument at any
of them makes a test fail. Archie and Gard reviewed the resolver change and
approved it; Gard re-reviewed the `install` warning and its summary line. One
warning-text edit (the "not added or updated" wording) followed that review and
was covered only by the full suite, not by a further review.

Not measured here: the native Windows and macOS suites, a run on a real WSL
machine with a Windows-only `claude`, the packaging dry-run, and the routing
and quality model evals that precede an instruction-changing release. The
effect of the instruction changes on model behavior is **UNMEASURED**.

The version in `package.json` and the lockfile has not been changed by these
notes. Publication follows the existing CI matrix, secret scan, tag-on-main
check and `npm` environment approval, with provenance. See
[releasing](../releasing.md).
