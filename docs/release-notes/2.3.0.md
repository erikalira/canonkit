# canonkit 2.3.0

## For users

**Action required: none.** Existing installations keep working. Uninstalling
installations from 2.2 or earlier requires manual cleanup (see below).

`canonkit uninstall` removes global artifacts recorded by `install` and
`reference`. Use `--dry-run` to preview, and `--claude`, `--codex`, `--opencode`
to select harnesses. Without flags it selects all recorded harnesses.

- The schema-1 manifest is `~/.canonkit/install-manifest.json`, with stable IDs,
  resolved roots, shared harness owners, provenance and hashes. It does not claim
  ownership of project specialists, external tool data or activity history.
- Edited owned agents, hooks, dashboards, skills and blocks are preserved in exclusive
  `.local.bak` copies, numbered on collision. OpenCode plugin backups live outside
  the auto-loaded plugins directory. Private snapshots/config backups can contain
  secrets; keep them out of dotfiles repositories.
  Observed artifacts remain intact, including edits, without creating a backup.
- Uninstall removes owned configuration before executable files and preserves
  unrelated user settings and text outside block markers. Codex trust shifts,
  OpenCode rule reordering, ambiguous provenance or known remaining references
  leave the affected harness in place with a manual cleanup message and exit 1.
- Interrupted file changes can be recovered from recorded before/after hashes.
  Concurrent config changes after preflight are refused rather than overwritten.
  An active command lock prevents overlapping canonkit changes.
- Reinstalling already-wired hooks preserves their recorded snapshot/hash pair,
  so unrelated settings edits do not block a later uninstall in any harness.
- Existing untracked global specialists are reported and preserved. Legacy
  `meu-time` history still migrates; its forwarder is updated with a backup and kept
  for manual removal because other projects may still reference it.

**Upgrading from 2.2 or earlier:** these versions did not write a manifest.
Without one, uninstall removes nothing and points to manual cleanup. Reinstalling
records identical preexisting artifacts as observed, which uninstall preserves;
actually replaced artifacts retain a backup and modified provenance. Preexisting
wiring can therefore need manual removal. There is no force/adopt option.

The 3.0 cleanup of byte-identical `~/.agents/<core>.md` leftovers is not part of
this release. Those files, activity history, backups and project data stay.

Details and manual cleanup: [installation reference](../install.md#uninstalling).
