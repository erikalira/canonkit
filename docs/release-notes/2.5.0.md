# canonkit 2.5.0

## For users

**Action required: none.** Existing installations keep working. Re-run
`npx canonkit@2.5.0 install` with your existing target flags to update agents,
blocks and core skills. Project specialists still require their own `add`
command. Installed files are updated only when you run the installer.

- Engineering protocols now make completion claims depend on current evidence.
  Bob uses hypothesis-driven debugging and selective regression-first testing;
  Quinn distinguishes requirements compliance from technical quality in the
  existing review. LOW work retains proportional testing and review.
- Scott's discovery guidance separates decisions from assumptions and covers
  constraints, negative paths and observable outcomes without repeating
  discovery already recorded by the project.
- Existing handoffs carry compact resumable state, validation limits and pending
  decisions. Readiness remains separate from authorization to commit, merge,
  publish or remove a worktree. Project decisions and durable preferences stay
  in versioned instructions or project artifacts.
- `canonkit tool add graphify` can maintain a bounded `.gitignore` block for
  generated graph output. It preserves existing project rules, reports already
  tracked output and supports dry-run inspection. It does not untrack files;
  removing the integration leaves the ignore block for explicit cleanup.
- The team guidance clarifies safe branch upstreams, repository handoffs and
  temporary work. Supporting documentation describes existing telemetry and
  its coverage limits without adding collection.

Security gate behavior is unchanged from 2.4.0: repeated edits still require
their normal confirmation, and scratchpad files have no new exemption. This
release does not include ask-once behavior or quoted-arrow suppression.

Usage: [engineering protocols](../team.md), [tool integrations](../tools.md),
[telemetry](../telemetry.md) and [eval limits](../evals.md).

resident-profile test and all eight enforced-rule checks. Resident source

establish portability of the original Windows/CRLF validation command.

New engineering fixtures are calibrated offline. Real-model efficacy, quality
gains, token savings and native cross-runtime behavior remain **UNMEASURED**.

release have not been rerun for this version; preparing the version does not
complete that release check.

versions agree, 30 focused offline tests passed, and the packaging dry-run
contained 53 files with no local runtime settings or generated integrations.
