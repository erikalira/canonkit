# canonkit 2.2.0

## For users

**Action required: none.** No gate changes until you opt in with `--wire-hooks`.
A plain install now also writes the Codex block, and moves the Codex agents if you
set `CODEX_HOME` (both below). To have the gates in Codex or OpenCode, run:

```bash
npx canonkit install --codex --wire-hooks      # then run /hooks in Codex once to trust it
npx canonkit install --opencode --wire-hooks   # OpenCode 2 or later
```

Then run `npx canonkit doctor`. Both hooks fail open: Codex shows nothing, and
OpenCode's one warning shows only under `opencode --print-logs`. `doctor` is where
a broken install shows up.

**If you set `CODEX_HOME`:** the Codex agents now go to `$CODEX_HOME/agents`, where
Codex reads them, instead of `~/.codex/agents`. The old copies in `~/.codex/agents`
are left in place; delete the 10 core names there by hand.

### Changes

- **`--wire-hooks` works with `--codex` and `--opencode`.** It was refused before.
  It now wires the hook of each runtime in the install, and only those.
  - **Codex:** the adapter and a copy of the core in `$CODEX_HOME/canonkit/`, and
    one `PreToolUse` group (`Bash|apply_patch`) in `$CODEX_HOME/hooks.json`.
  - **OpenCode 2+:** its adapter, the core and `package.json` in
    `~/.config/opencode/canonkit/`, the plugin in `plugins/canonkit.js`, and two
    `ask` rules (`git commit *`, `git push *`) appended to `opencode.json`
    `permissions`.
  - Each config file it changes gets a dated `.canonkit-<timestamp>.bak` first.
    Every file and key is listed in
    [install.md](../install.md#codex-hook---wire-hooks).
- **Two gates in Codex and OpenCode, once wired:** the git hook and signing bypass
  block (`--no-verify`, `--no-gpg-sign`, `-c core.hooksPath=...`) and the secret
  block. Both deny, with the same reason as in Claude Code. The other gates hold
  by judgment there; the table is in [hooks.md](../hooks.md#codex-and-opencode).
  Each was seen denying in a real session: Codex `codex-cli 0.166.0` and OpenCode
  `v2.1.4`, both on Windows 11.
- **`$CODEX_HOME` is honored** for every Codex path: agents, block and hook.
- **A Codex block** in `$CODEX_HOME/AGENTS.md`. Codex does not read `~/AGENTS.md`
  from a repository below your home folder, so the block points at it.
  `doctor` WARNs if an `AGENTS.override.md` hides the block.
- **The OpenCode block** marks the two gates `[ENFORCED]` and names what is not
  gated.
- **`doctor`** adds rows for the Codex and OpenCode hook files (byte for byte with
  the package), the Codex `hooks.json` group, the OpenCode asks, and each block.
  The rows appear only where canonkit wrote something for that runtime.
- Install refuses before writing anything when it would have to guess: a
  `hooks.json` or `opencode.json` that does not parse, an `opencode.jsonc`, a
  `CODEX_HOME` path holding `"`, `$` or a backtick, or an OpenCode older than 2 or
  of unknown version.
- No change in behavior of any Claude Code gate.

### Known gaps

- OpenCode's `execute` tool and MCP tools are not gated.
- OpenCode's asks match the command as typed: `git -c user.name=x commit` runs
  without a prompt. `opencode run` rejects an ask, and `--auto` approves it.
- Code swapped into `canonkit/` runs without review. Codex's `/hooks` trust covers
  the command, not the files, and OpenCode has no trust step. `doctor` catches
  the change.
- `doctor` is not target-aware yet: a Codex- or OpenCode-only install still gets
  `FAIL` rows for the Claude Code half.

### Rollback

There is no `uninstall` command. To undo the wiring, remove by hand what
[install.md](../install.md#uninstalling) lists for Codex and OpenCode: the
`canonkit/` folder, the `hooks.json` group or the OpenCode plugin and its two
`permissions` rules. Restoring a `.bak` also works, but undoes any later change
you made to that file. The `.bak` files hold the whole file, secrets included:
delete them when you no longer need them.

## Internal

- `hooks/canonkit-codex.js` and `hooks/canonkit-opencode.js` are adapters over the
  pure `evaluate()` core. Each declares its own gate modes, and tests discover
  every adapter and check that its map covers every gate kind.
- The `apply_patch` reader (`parsePatch`) moved into the core, shared by Codex and
  OpenCode.
- A missing `cwd` no longer fails open: the deny gates still decide.
- `scripts/check-enforced.mjs` (run by `validate.sh`) checks that every
  `[ENFORCED]` rule names a gate its harness's adapter enforces, and that the
  harness has a "Verified on" row in `docs/hooks.md`.
- The context-size band state moved out of `evaluate()` into the Claude adapter,
  so the core writes nothing.
